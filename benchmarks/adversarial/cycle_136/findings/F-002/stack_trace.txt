The harness's assertion `assert oracle_for == parser_for` failed for any
input containing a quoted `for=` value with an escape sequence. The bug is
in `_oracle_extract_for_values` (line ~50 in
 benchmarks/adversarial/cycle_136/harness_cross_cycle.py), which performs
 `v = v[1:-1]` after a `startswith('"') / endswith('"')` check, with no
intermediate escape-resolution pass.
